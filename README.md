# AI 项目拆分组装法（ai-project-split-assembly）

> A practical, six-phase engineering playbook for building AI applications with large language models — born from real construction-industry project management practice, battle-tested through five rounds of independent review.

**一句话**：把建筑工程的施工图思维用在 AI 项目上——**立项定总框架 → 施工图设计（100% 完美 + 5% 瑕疵处置）→ 分包照图施工 → 模块化组装 → 竣工验收 → 运维复盘**，全程文档即事实源、状态门只认证据。

## 为什么需要这套方法

AI 项目有三个传统项目管理管不住的痛点：

1. **AI 没有记忆**——对话历史全靠重读，长项目必然丢失信息、漂移跑偏；
2. **AI 输出不可自证**——"我完成了"不能信，必须靠校验器和证据说话；
3. **token 是成本**——上下文越长越贵、越稀释注意力，必须拆小、拆独立。

这套方法把**「项目拆分组装法」**（用总框架约束全局 → 拆分细分模块 → 每模块预留上下游契约接口 → 组装）与**工程化项目管理**（阶段准入、变更控制、缺陷闭环、竣工验收）融合，适配所有通用大模型，也适配个人单干与团队协作。

## 六阶段主线

```
① 立项        调研 + 初设 + 总框架（目标卡·选型·PoC·PRD·契约骨架·评测基线）
      ↓
② 详细设计    施工图设计：为后续每一步任务画图，执行者零思考、照图施工
      ↓        100% 完美标准出图 + 预设 5% 瑕疵处置方案（三级处置通道）
③ 实施        拆分六规则 → 上下游契约细化 → 分包施工 → 分包验收 → 多线管理
      ↓
④ 组装        逐环联调（契约=标准件，校验器=检具）→ 总验收 → 整改
      ↓
⑤ 竣工        验收单签字 → 竣工图归档（运维对比原点）→ 灰度上线 → 回滚预案
      ↓
⑥ 运维        四维监控 → Badcase 闭环 → 数据回流 → 复盘入库
      └──────────────── 反哺下一项目立项（先查后造）←──┘
```

**三条贯穿暗线**（全程生效）：
- **状态门 + 进度总览**：任务只认五态（待开工/进行中/待验收/已通过/受阻），推进只认证据（命令+输出）
- **变更通道三级分级**：①登记免确认（机械可判定）②轻评审（补图/加用例）③实时确认（改契约语义/Prompt 行为定义）
- **文档即事实源**：docs/ 是唯一真理源，工具私有记忆只是缓存

## 核心机制速览

| 机制 | 一句话 |
|:---|:---|
| 目标确认卡 | 真实目标/完成标准/范围边界/关键约束 + 止损线（含触发后动作） |
| 双明确准入 | 需求冻结 + 方法冻结（PoC 指标达标）才允许进施工图设计 |
| 任务施工图 | 七要素：内容/分步方法/材料清单/验收标准/边界异常/工期/关联需求 |
| 零思考走查 | 施工图交给未参与设计的新会话按图执行，需思考处=没画到位；**走查必须跨模型**（防共同盲区） |
| 拆分六规则 | 内聚最大化、按依赖拆、包可独立验收、易变隔离、按图分册、拆完预演 |
| 契约冻结 | 细化只补子条目不改编号；改编号=升版=走变更单 |
| 状态门 | 只认证据，草稿≠通过 |
| 三档裁剪 | 全量/标准/轻量 × 人力维度——机制密度不压垮小项目 |
| 复盘入库 | 参数（触发线/瑕疵率/止损线）实测校准，反哺下一项目 |

## 快速开始（30 秒）

1. 新项目 → 读 `docs/00-总览-融合蓝图.md` 确定所处阶段；
2. 读对应阶段文档，按流程产出交付物；
3. 项目规模小？按「三档裁剪」走轻量档：目标确认卡 + 契约 + 任务清单 + 进度总览，其余免。

**触发判据**（满足任一启用全套机制）：功能模块 >3 或子代理 ≥4；单会话上下文超 20 万 tokens 作事后校准判据。

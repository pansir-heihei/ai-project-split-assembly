# 阶段 1：立项（调研 + 初设 + 总框架）——6 阶段定稿版

> 状态：**已定稿 V2.4**（2026-08-17；变更记录见文末）
> 上游接口：用户想法 / 业务方需求（本阶段入口，无文档依赖）
> 下游接口：向阶段 2 输出总框架（PRD 定稿、契约骨架、评测基线）与《技术方案书》（选型决策、PoC 结论）

---

## 一、阶段定位

**用户原话要旨**：立项 = 原来的立项 + 初设 + 总框架等——调研、初步设计、总框架一条线走完，为施工图设计（阶段 2）备齐"双明确"前提。

一句话：**把"要做什么"（需求）和"用什么方法做"（方案）都钉死，并立好总框架宪法。**

## 二、融合后完整流程

### 步骤 0：先查后造
检索现成方案：开源项目、现成工具/API、公司既有资产、知识库历史案例（含上次复盘沉淀）。查过什么、为什么不用，一句话记录。

### 步骤 1：目标确认卡（含止损线）
四要素全部可判定：**真实目标**（解决 XX 场景 YY 问题达到 ZZ 效果）/ **完成标准**（可测量：准确率、成本、效率）/ **范围边界**（做什么 + **不做什么**）/ **关键约束**（预算、时间、合规、算力）。
- **止损线**：最大投入金额 + 最大投入时间 + **触发后做什么**（转 API 方案 / 砍功能 / 暂停）——只定线不定义动作，线就是摆设。
- **成本口径统一定义（V2.2）**：成本 = API 调用费 + 算力（GPU/云）+ 人力折时，三列分记——止损线（本阶段）、燃尽项（阶段 3）、增量压测（阶段 4）、全链路压测（阶段 5）按**同一口径**记账，才能对账。
- **澄清前置**：含糊处当场问清（给 2~4 选项 + 各自影响），不把歧义带进后续文档。
- 用户确认后才进入下一步。

### 步骤 2：数据资产盘点
按盘点表执行：数据源、类型、量、质量（1-5）、标注、更新频率、获取难度、合规风险。

### 步骤 3：技术路线比选（前期决策优先）
给 **2~3 个候选方案**（直接 API / 微调 / RAG / 自研 / 现成开源），对比维度：成本、效果、周期、可控性；写利弊与推荐项，**用户拍板**，决策记录留档（后续换路线 = 关键变更，走变更单）。

### 步骤 4：PoC = 最小验证
- 先问：本项目**最险/最没把握的一段**是什么？
- 只验证这一段，end-to-end 跑通 1 个案例即可，不全面铺开；
- **判定标准（V2.2）**：PoC 结论必须回答"最险点对应的指标是否达到立项目标的最低线"（如检索准确率 ≥70%）——"跑通 1 个案例"只是必要条件，**指标达标才算成立**；**成立** → 写《PoC 验证报告》进下一步；**不成立** → 立即停下，说明"错在哪、代价、怎么退回"（回步骤 1/3），不带着风险进详细设计。

### 步骤 5：规模预判（拆分组装法启用判定，V2.2 明确口径）
触发判据（满足任一即启用）：
- **主判据（立项时可操作）**：功能模块数 >3 或预计子代理 ≥4——直接数得出来；
- **校准判据（事后校准）**：单会话累计上下文超 **20 万 tokens**（成本机制，与上下文长度无关）——用同类历史项目实测数据回填参考；本项目实测值记入阶段 6 复盘校准。
- 判定结果写入立项报告；按总览「三档裁剪」选择执行档位。
- **量化基准冷启动（V2.3）**：首次项目无实测数据时用初始参考区间——单任务包 0.5~2 人天、瑕疵率 3%~8%（按项目类型：RAG 类偏下、生成类偏中、Agent 类偏上）；实测值由阶段 6 复盘回填修正。

### 步骤 6：总框架（宪法）
1. **《产品需求文档-PRD》定稿**：F1/F2…逐条可判定句子（"当…时，系统应当…"）、不做的范围、验收标准、变更记录表（初始空）；任何会话对需求有冲突，以 PRD 为准。
2. **契约骨架**：模块边界与数据流图、全局 schema 框架、模块间 API 签名框架、统一 id 前缀、**契约冻结规则**（改契约先停下报告→用户确认→升版；**分级细则见 03 §步骤 7**：①级向后兼容新增子条目免确认）。任务包级细化留给阶段 3。
3. **评测基线冻结**：P0/P1/P2 指标体系、核心评测集基线版本、通过阈值（P0 必须 100%）、Badcase 定义标准（什么算错、谁判定）。
   - 评测集构建口径（V2.2）：ground truth 来源、用例量级下限（P0 用例 ≥ 核心场景最小集）、标注成本预算——冻结时一并记录，防 Goodhart 风险从评测集侧转移到构建侧。

## 三、检查清单

- [ ] 目标确认卡四要素齐全 + 用户已确认（含澄清前置）
- [ ] 止损线已设定（金额 + 时间 + 触发后动作）
- [ ] 先查后造已完成（查过什么、为什么不用现成）
- [ ] 数据资产盘点表完成 + 获取成本评估
- [ ] 技术路线比选完成（≥2 候选、用户拍板、决策记录留档）
- [ ] PoC 最小验证完成（最险点明确、结论明确、回退路径明确）
- [ ] 规模预判完成（拆分组装法启用与否已判定）
- [ ] 合规风险已评估（数据隐私、版权、行业监管）
- [ ] PRD 定稿（F 编号、不做的范围、验收标准、变更记录表）
- [ ] 契约骨架 + 评测基线冻结（变更须走变更单）

## 四、交付物

| 交付物 | 说明 |
|:---|:---|
| 《立项报告》 | 目标确认卡（含止损线）、数据盘点、选型决策记录、PoC 结论、规模预判与启用判定、风险、变更记录表 |
| 《技术方案书》 | 选型比选表 + 决策记录 + 架构图（数据流/模型流/业务流，含模块边界与接口点）+ PoC 结果 |
| 《PoC 验证报告》 | 最险点、方法、结果、结论、回退判定 |
| 《产品需求文档-PRD》定稿 | 总框架宪法之一 |
| 《接口契约》骨架 v0.x | 总框架宪法之二（阶段 3 细化任务包级） |
| 《评测基准》 | 评测集冻结基线、P0/P1/P2、通过阈值 |

## 五、与后续阶段的接口

| 下游阶段 | 拿什么 | 注意什么 |
|:---|:---|:---|
| 阶段 2 详细设计 | PRD 定稿 + 契约骨架 + 评测基线 + 架构图（模块边界） | 双明确（需求+方法）是阶段 2 准入条件，缺一不可 |

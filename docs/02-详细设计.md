## 一、阶段定位（用户核心思想）

**用户原话要旨**："需求非常明确、方法比较明确之后进入详细设计阶段，也就是施工图设计阶段——为后续的每一步任务进行详细规划，后续完全不需要思考该怎么做，完全按照施工图完成施工图明确的设计内容。"

**设计标准（用户修正）**：按 **100% 完美标准**出图——每个任务都画到位，不留设计空白（= 设计覆盖率 100%）；**同时预设约 5% 瑕疵处置方案**（= 执行偏差预算，非质量容忍）：即使 100% 努力，实施中仍可能出约 5% 偏差，为它预先备好处置通道。

## 二、进入条件（双明确准入）

1. **需求非常明确**：目标确认卡用户已确认（**含第 0 要素「用户需求因果链」八问已答清并在 PRD 文首/进度总览常驻**，V2.7）+ PRD 冻结（F 编号齐全、**需求链式条目（使用层+响应层）**、不做的范围明确、验收标准齐备、**核心验收指标在列**）。
2. **方法非常明确**：技术方案已确认（选型用户拍板）+ PoC 成立（最险点已验证）。
- 任一不满足 → 回阶段 1 补齐（需求模糊回目标确认卡；方法未定回比选/PoC），**不允许进入本阶段**。
- **设计波次（V2.1 正式机制）**：AI 项目存在认知型不确定——真实数据分布上的表现、规模化后才暴露的边缘 case、干系人看 demo 后改需求，这些往往不是执行偏差（B 类），而是**设计假设被证伪**。为此：远端不确定模块允许「框架图 + 开工前补图」成为**常态路径而非例外**（补图走轻评审，不阻塞全局）；变更通道按三级分级承接（见 03 §步骤 7），避免变更流程本身成为瓶颈。
- **补图截止节点（V2.3）**：对应任务包开工前 1 个迭代周期必须完成补图与走查，逾期该任务包顺延——补图无休止 = 项目失控。

## 三、施工图设计范围（三方面，用户明确）

**设计第一原则：用户视角（V2.7 新增，用户定）**——不是为了设计而设计，设计就是为了用户使用；站在用户角度设计才是有价值的设计。每个设计决策对照**用户三层次（V2.8 用户定稿）**：**①能用**（功能可靠可达、结果可信）→ **②好用**（简单易操作、符合用户希望的方式）→ **③想用**（最好的方式、用户主动愿意用——不只是"不拒绝"，而是"想回来"）；每条设计能追溯到需求链哪一问，追不到=不要做。

三方面全部从用户角度出发（不只是装饰美观）：

| 设计方面 | 站在用户角度问 | 反例 |
|:---|:---|:---|
| 主体框架设计 | 用户的使用路径顺不顺（几步到达目标、切换是否流畅） | 架构整齐但用户绕三次菜单 |
| 功能设计 | 这是用户**要**的功能吗（从需求链②溯源） | 做了 10 个功能用户只用 2 个 |
| 装饰美观设计 | 用户看得懂吗、摸得着吗（认知负担、操作直觉） | 界面漂亮但找不到按钮 |

1. **主体框架设计**：架构、数据管道（采集→清洗→标注/向量化→存储→版本管理，含异常分支）、模块边界、全局 schema。
2. **功能设计**：每个功能模块的详细设计——输入/输出/步骤/异常/验收，画到照图施工粒度。
3. **装饰美观设计**：界面、样式、交互设计。
   > **注意（模型弱项）**：美观类施工图模型可给方案，**最终判断必须人工评审**，不让模型自己定稿。

## 四、融合后完整流程

### 步骤 0：前置确认
核对双明确清单 → 通过才进入设计。

### 步骤 1：施工图总说明（全局约定）
PRD 定稿（阶段 1 已出，此处复核）+ 契约骨架复核 + 评测基线 + 数据规范 + 异常兜底策略（超时/失败/幻觉/敏感内容/空输入，并入错误码表）。

### 步骤 2：分项施工图设计（本阶段灵魂）
- **任务边界按「内聚最大化」设计**：常一起变的画进同一张图、同一任务边界（与阶段 3 拆分规则 1 联动——图纸边界就是拆分边界）；
- 每个任务一张**任务施工图**（七要素模板）：施工内容 / 施工方法（分步，细到无需设计决策：查什么资料、调什么函数、按哪个 schema、异常走哪个错误码）/ 材料清单（引用契约条目）/ 质量验收标准（命令+预期输出）/ 边界与异常 / 预估工期 / 关联需求 F 编号；
- **画图成本上限**：画图成本 < 返工成本；能确定的画细，不确定的标"开工前补图"。

### 步骤 3：施工图走查（零思考验证——必须跨模型/跨工具）
1. 每张图交给**未参与设计的新会话执行**（模拟或真实执行首包）：按图走一遍，标出所有"需要思考"的地方；
2. **跨模型/跨工具强制（评估关键强化）**：同一模型画图 + 同一模型走查 = 共同盲区——走查必须用**不同模型或不同工具**（如 flash 画的图让 pro 走查；或用真实执行首包代替模拟走查）；
3. **走查分级（V2.2 明确抽样方法）**：核心契约与 P0 链路施工图**强制跨模型（100%）**；非核心按**风险加权**抽样（≥30%）；同模型新会话走查显式标注「降级方案，残留共同盲区风险」，不视为通过；
4. 需要思考处 → 补图 → 复走查；全部通过 → 进入评审。
5. **用户视角走查（V2.7，与跨模型走查并行）**：假设真实用户第一次使用——他能不靠说明走通核心链路吗？无引导走通 = 过；走不通 = 设计重来。分工：跨模型走查管「图清不清楚」（执行者零思考），用户视角走查管「好不好用」（用户零门槛）——**两者都过，才冻结施工图**。

### 步骤 4：施工图评审与冻结
- 用户/技术负责人评审通过（美观设计必须人工评审）→ **施工图冻结**（v1.0 起，变更须走变更单）；
- 评审通过即宣告：**除波次补图（走轻评审）外，执行阶段不再有设计工作，只有施工与证据采集。**

## 五、5% 瑕疵处置方案（预设通道）

| 级别 | 类型 | 处置 | 是否停工 |
|:---|:---|:---|:---|
| A 类 | 施工图缺陷（图错/图漏） | 补图改图 → 变更单升版 → 受影响任务包重走验收 | 暂停该任务 |
| B 类 | 执行偏差（照图做但偏了） | 记录纠正 → 回归验证（不涉图）；**同类偏差 ≥3 次升级为 A 类**（图表述有歧义） | 不停 |
| C 类 | 外部变化（需求/环境变） | 走变更通道 → 评估影响范围 | 按评估 |

流程：发现 → 当天录台账（与 Badcase 台账**合并一张**）→ 分级 → 处置 → 回归验证 → 关闭。
**瑕疵率监测（V2.2 双条件，防小项目误触发）**：触发复盘 = **绝对数 + 比例双条件**——瑕疵条数 ≥3 **且** 比例 >5%（比例 = 瑕疵条数 ÷ 已验收任务包数）；任务包 <10 的小项目**只用绝对数**（≥3 条）；"持续" = 连续 2 个迭代周期（单次交付项目 = 连续 2 个验收批）。**5% 是待校准假设**——由阶段 6 复盘数据逐项目修正（已挂入 06 复盘清单）。

## 八、模板：任务施工图（七要素）

```
施工图编号：Sx-任务名 | 版本：v1.0（冻结于 2026-XX-XX，变更走变更单）
1. 施工内容：交付什么 + 交付物清单
2. 施工方法（分步）：Step1/2/3…（方法、工具、输入、参考契约哪条）
3. 材料清单（引用契约条目，不另起炉灶）：输入 / 输出 / 工具依赖
4. 质量验收标准（命令 + 预期输出 + **性能/成本预算**）：校验器 → PASS；评测集 P0-xx → xx；延迟 P99 ≤ __ms；单次调用成本 ≤ __元
5. 边界与异常：超时 → 错误码 1003 走兜底；空输入 → 1001；敏感内容 → 1002
6. 预估工期 + **预估上下文预算**（V2.4，token 是体系一级目标）：__ 会话/人天、约 __k tokens；实测值随交付报告记录，阶段 6 复盘回填
7. 关联需求：F1、F2（对接需求追踪映射表）
```
> 填好示例见 `14-施工图填好示例.md`。

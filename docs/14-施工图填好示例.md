# 示例：一张填好的任务施工图（智能客服问答 S2）

> 用途：参照示例——看"填好"的施工图长什么样，再对照 `02-详细设计.md` 模板 1。
> 说明：示例项目为虚构的智能客服问答（与阶段 2 模板同源），步骤已细到"执行者零思考、照图施工"。状态：**已定稿 V2.8**。

---

```
施工图编号：S2-智能客服问答接口 | 版本：v1.0（冻结于 2026-08-16，变更走阶段六）

1. 施工内容
   实现 /api/v1/chat 接口：接收用户问题与上下文，返回模型回答、置信度与引用来源。
   交付物：app/api/chat.py、tests/test_chat_contract.py、契约级测试证据（命令+输出截图）

2. 施工方法（分步，照此执行，不需要思考）
   Step1  在 data_models.py 定义 ChatRequest / ChatResponse（字段照契约 3.1，
           session_id 用前缀 s_，user_query 最长 500 字）
   Step2  实现 POST /api/v1/chat 主流程：
          ① 解析请求体 → ② 跑校验器 validate_request（不通过→按错误码返回）
          ③ 调 RAG 检索服务（top_k=5, threshold=0.7，接口照契约 5.2）
          ④ 组装 prompt（system prompt v0.4，照契约 6.1；history 最多 5 轮）
          ⑤ 调模型 API（超时 10 秒）→ ⑥ 包装响应（照契约 3.1）
   Step3  异常分支（照契约错误码表）：
          超时 → code 1003 + 走兜底缓存回答
          敏感词 → code 1002 + 不输出任何内容
          空输入 / 超长（>500 字）→ code 1001
   Step4  写契约级测试 tests/test_chat_contract.py：
          5 组样例输入（正常/带历史/空输入/超长/敏感词），
          每组断言响应通过 schema 校验（调校验器 validate_response）

3. 材料清单（引用契约条目，不另起炉灶）
   输入：契约 2.3 数据 schema（data_models.py ChatRequest）
   输出：契约 3.1 响应 schema（ChatResponse）
   依赖：RAG 检索服务（S1 交付，契约 5.2）；模型 API 配置（契约 6.2）

4. 质量验收标准（命令 + 预期输出）
   python scripts/validate_contract.py      → 全部 PASS
   pytest tests/test_chat_contract.py       → 5 passed
   评测集 P0-01（3 秒内应答）：压测脚本     → P99 = 2.1s ✅（≤3s）

5. 边界与异常（照契约错误码/兜底策略）
   超时 → 1003 兜底缓存；敏感内容 → 1002 不输出；空输入/超长 → 1001

6. 预估工期：2 会话

7. 关联需求：F1（3 秒应答）、F2（敏感内容拦截）——对接需求追踪映射表
```

## 怎么检验这张图"画到位"了（零思考走查演示）

把图交给一个**没参与设计的新会话**模拟执行，会问的问题全在图里：

| 新会话可能问 | 图里哪行回答 |
|:---|:---|
| 字段怎么定义？ | Step1 + 材料清单（契约 3.1） |
| 检索参数用多少？ | Step2-③（top_k=5, threshold=0.7） |
| system prompt 用哪版？ | Step2-④（v0.4，契约 6.1） |
| 超时了怎么办？ | Step3 + 边界与异常（1003 兜底） |
| 怎么算做完？ | 质量验收标准（3 条命令+预期输出） |

**凡是执行者需要停下来思考"该怎么做"的地方，就是图没画到位——补图后再评审。**

## 与"开场白"的关系

这张图就是拆分组装法「会话开场白」的完整形态：新会话只读施工图 + 契约即可开工，零上下文、零设计决策。

## 一、融合目标

两套方法论融合为**一套以 6 个工程阶段为主线的统一体系**（用户 2026-08-16 亲自确定的阶段划分，最高权威）：

- **主线**：立项 → 详细设计 → 实施 → 组装 → 竣工 → 运维，阶段准入制保留。
- **融入**：拆分组装法全部机制（总框架、任务包拆分、上下游契约接口、状态门、交接简报、需求追踪、省 token、文档即事实源、变更通道）+ 手册的量化评测 P0/P1/P2、缺陷闭环、止损线、阶段准入。

## 四、三条贯穿暗线（全程生效）

1. **状态门 + 进度总览**：任何会话/工具先读再干活；状态只认证据（命令+输出）。
2. **变更通道（V2.1 三级分级）**：①**登记免确认**——契约新增子条目且向后兼容、B 类执行偏差：直接处理，事后补确认；②**轻评审**——施工图补图（不涉契约语义）、评测集加用例：批量提报，用户抽批；③**实时确认**——改契约编号/语义、改施工图冻结内容、改验收标准、改 Prompt（Prompt 是 LLM 模块行为定义，归高风险）：停下→用户确认→升版→补任务包。**四级连锁**（契约→施工图→任务包→交付报告）用变更单「逐级勾销清单」防漏。
3. **文档即事实源**：docs/ 唯一真理源，工具记忆只是缓存。**文档索引与归档约定**：每项目一份索引（活文档清单）；过时文档移入 `归档/` 子目录，不堆积。

## 五、大模型适配性结论（已确认）

文档驱动分步执行、外部记忆、输出必须验证、上下文小而专、人机分工（人管方向/决策/验收，模型管生成/起草/执行）、最小验证先行。适配所有通用大模型；**执行载体四选一**：后台子代理 / DSH goal / Ralph 验证轮三个是 DSH 工具能力，「真·新会话」为跨工具通用——文档已注明。角色与权限（用户/总控/分包/独立验收/走查人 RACI）见 `03-实施.md`。

**三档裁剪（V2.2，回答"谁在什么规模下怎么裁剪"——机制密度不再压垮小项目）**：
- **全量档**：模块 >3 或子代理 ≥4 → 六阶段全套机制；
- **标准档**：模块 2~3 个 → 目标确认卡 + 契约 + 施工图 + 分包验收 + 进度总览；台账/走查/多线管理简化；
- **轻量档**：单模块小项目 → 目标确认卡 + 契约 + 简化任务清单 + 进度总览；跳过台账、走查、多线管理。
- **人力维度**：单人多角色场景另有裁剪（见 03 角色节）——写权隔离降级、跨模型走查强制。
- **最小机制清单（V2.4，让裁剪可判定）**：轻量档 = 目标确认卡 + 契约 + 任务清单 + 进度总览，**其余一律免**；标准档 = 轻量档 + 施工图 + 分包验收 + 简化台账。**（V2.5 补充）本质核心前置、核心验收用户亲验为不可裁剪项，三档全保**——裁剪只裁管理密度，不裁方向把关。
- **管理开销红线（V2.4）**：管理动作耗时占比 **>30% 触发裁剪降档复核**——管理开销超过收益 = 机制空转或被执行者绕过，这是方法论方案的典型死因。

**操作口径速查（V2.4，执行者零思考的兜底）**：
- **迭代周期** = 一个任务包从开工到验收的批次（单次交付项目 = 验收批）；
- **接管仪式** = 读进度总览 → 复述当前灯号/受阻项/下一步 → 用户确认，三动作；
- **风险加权抽样** = 按「契约引用数 × P0 关联度」排序取前 ≥30%。

## 一、阶段定位（用户原话要旨）

"运维"——运营期：监控、漂移检测、badcase 持续闭环、数据回流、复盘入库。

## 二、融合后完整流程

### 步骤 1：线上监控（四维度，V2.3 加合规巡检）
效果（准确率、满意度）、性能（延迟、错误率）、成本（调用费用）、**合规（内容安全巡检，与前三者并列）**；告警阈值设定（效果下跌超 X% 触发；**X 冷启动初值 = 相对竣工图基线下跌 5%（V2.4），挂入复盘校准**）。
**告警处置链（V2.4）**：告警 → 对照《应急预案》→ 回滚/降级 → 录台账（当天）——告警不是通知，是闭环入口。

### 步骤 2：模型漂移检测
输入分布漂移、输出分布漂移、概念漂移（对比《竣工图》基线）。

### 步骤 3：Badcase 持续闭环
线上用户反馈、客服转人工、自动抽检 → **当天录入瑕疵/Badcase 台账（同一张）** → 归因四层（落到契约条目）→ 修复 → 回归入集（走变更单）。
> 效果下跌超阈值 → 黄/红灯（阶段 3 灯号机制延续）→ 触发本闭环。

### 步骤 4：数据回流与再训练
线上优质数据回流 → **合规检查（V2.4，复用 03 步骤 3 口径：PII 脱敏核验 + 版权/授权核验，核验率 100%）** → 按数据规范版本入库（不可变存储）→ 定期迭代；实验记录表延续。入库后再发现合规问题 = 污染不可变存储。

### 步骤 5：定期评测（基线保护）
每周/每月跑核心评测集，对比历史趋势与《竣工图》原点；评测集本身变更（加用例/调权重）走变更单。

### 步骤 6：复盘入库（拆分组装法⑧落点，闭环回起点）
定期（里程碑/收尾）把以下写入知识库：
1. **目标确认卡校准**（当初怎么定的、实际偏差、下个项目预估修正）；
2. **关键决策**（选型、契约取舍，含决策记录）；
3. **踩坑**（典型 Badcase 根因、漂移事件、变更教训、瑕疵率数据）；
4. **机制参数校准（V2.1）**：触发判据（20 万 tokens）、5% 瑕疵率假设、止损线松紧、告警阈值 X——用本项目实测数据逐项修正，写回融合手册校准记录；**按项目类型（RAG/生成/Agent）分类沉淀实测值（V2.3）**，逐步形成组织级基准库，替代冷启动参考区间；
5. **管理开销校准（V2.4）**：每迭代/每包管理动作（变更单/台账/简报/走查）耗时占比实测并按项目类型沉淀；**>30% 触发裁剪降档复核**——管理开销超过收益 = 机制空转，是方法论方案的典型死因。
6. **核心验证结论（V2.5）**：本质核心是否成立（用户亲验结论）、核心假设→指标的验证过程与偏差、下一项目修正——核心结论不入库 = 下个项目重新踩坑。
> 产出《项目复盘.md》→ 知识库（已有体系：`你的知识库\`，按 memory 图谱索引 + notes 详情两级结构存放）→ 下一项目阶段 1「先查后造」直接检索。

## 一、阶段定位（用户原话要旨）

"组装总验收、整改"——模块化生产的组装车间：按契约把各模块连起来，总验收，不合格整改。

**边界写死（评估强化）**：**总验收结论在本阶段给出；签字在阶段 5 竣工。** 组装与竣工是一件事两步，不写清会扯皮。

## 二、组装机制（模块化生产类比，用户确认）

| 用户类比 | 机制实现 |
|:---|:---|
| 模块完美连接 | 接口契约 = 标准连接件（模块只经契约通信，不直读内部） |
| 连接合格保证 | 校验器 = 出厂/现场检具（schema 校验） |
| 完美连接靠什么 | 提前定义 + 契约冻结（各包并行对着同一份契约生产） |
| 组装怎么进行 | 按数据流逐环联调，过→下一环，不过→定位模块打回 |

**三层保障**：静态层（schema 校验）→ 动态层（契约级测试）→ 集成层（端到端联调）。

**诚实提醒**：连接失败是正常事件，机制保证"失败可定位、可修复、可追溯"，而非"永不失败"。

## 三、融合后完整流程

### 步骤 1：组装（逐环联调 + 增量压测）
1. 按契约数据流**逐环联调**：S0 骨架 → S1 数据 → S2 功能 → S3 界面…，每环跑 schema 校验（校验器），过→下一环；
2. **增量压测（V2.1）**：每拼上一环即测延迟/成本增量，对照施工图性能预算——NFR 不当"竣工彩蛋"，逐环验证，超标就地定位该环；
3. **打回机制（V2.2，与阶段准入制衔接）**：任何一环不过 → 定位为该模块问题，**瑕疵台账记 A/B 类**；打回**不是**重走阶段 3 全部流程——被打回模块进入**整改子流程**：归因四层（见步骤 3）→ 修复（复用 03 步骤 5 验收标准）→ 重跑受影响包验收留证据；**打回次数上限 2 次**，第 3 次仍不过 → 升级为重新立项或触发止损线复核；
4. **只做联调与缺陷修复，不新增功能**（新增功能 = 蔓延，拒绝）；
5. **组装 ≠ 完工**：拼起来只代表"连接成功"。

### 步骤 2：总验收（对照总框架逐条）
1. 打开《进度总览》需求追踪映射表（F1/F2 → 任务包 → 验收证据）；
2. **查漏**：没有任务包认领的需求 = 漏项 → 补任务包（回阶段 3）；
3. **查蔓**：没有需求来源的功能 = 蔓延 → 删或补 PRD（走变更单）；
4. 对照 PRD 验收标准**逐条核对证据**（命令+输出）；
5. 核心评测集指标达标（对比冻结基线）；
6. **评测集覆盖度复核（V2.1，防 Goodhart）**：用联调真实样本抽检评测集代表性——确认冻结基线仍代表目标分布；发现覆盖空洞 → 走变更单补集（不是改基线，是补盲区）；
> **两层验收分工（V2.2）**：分包验收管**模块内**达标（P0 100%）；总验收管**跨模块集成态**——联调回归集 P0 100% + 查漏查蔓 + 覆盖度复核，不做重复劳动；"P0 清零"要求 = 联调回归集 P0 100%。**合规 P0（V2.3）**：内容合规检测、Prompt 注入防护测试在集成态复验通过。
7. P0 Badcase 清零（P1/P2 有明确修复计划）。
- 产出《总验收结论》：逐条达标清单 + 查漏查蔓结果。
- **台账反向抽查（V2.4）**：总验收时抽查台账/进度总览与交付报告、证据链的一致性（每项目 ≥3 条样本）——写权隔离防的是分包越权，不防总控笔误。

### 步骤 3：整改（缺陷闭环在此用）
- 总验收差距 → 归因四层（数据/模型/Prompt/工程，落到契约条目）→ 修复 → 回归验证（评测集+校验器）；
- **回归入集须走变更单**（入评测集 = 评测集变更，冻结基线保护，防"为达标改尺子"）；
- 整改完成 → 复验 → 更新《总验收结论》。

## 四、检查清单

- [ ] 逐环联调完成：schema 校验逐环过（证据在案），联调中未新增功能
- [ ] **增量压测逐环执行**（延迟/成本对照施工图预算，V2.1）
- [ ] 组装边界清晰：总验收结论在本阶段给出，签字在阶段 5
- [ ] 需求追踪查漏完成：无漏项（无主需求）、无蔓延（无源功能）
- [ ] PRD 验收标准逐条过（命令+输出证据）
- [ ] 核心评测集指标达标（对比冻结基线）
- [ ] **评测集覆盖度复核完成**（真实样本抽检代表性，V2.1）
- [ ] P0 Badcase 清零；P1/P2 有明确修复计划
- [ ] 整改闭环完成（归因四层→修复→回归→入集走变更单）

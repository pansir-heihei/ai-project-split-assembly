## 二、新项目三步定位法

1. **定位**：开 00-总览 → 6 阶段映射表 → 确认当前阶段；
2. **执行**：读对应阶段文档 → 按流程走 → 产出交付物；
3. **接力**：每个阶段产出即下一阶段输入（各文档末尾有"与后续阶段的接口"表，照表衔接）。

## 三、与拆分组装法技能的关系

- 技能 `multi-session-project`（`skills/multi-session-project/SKILL.md`）= **核心方法**（总框架→拆分→细分框架+契约→组装 + 状态门/交接简报/需求追踪/省 token）；
- 融合手册 = 技能在**6 工程阶段框架下的完整展开**；
- 冲突时技能为准（核心机制），融合手册为流程细节；
- 触发判据（V2.2 口径）：**主判据** = 功能模块数 >3 或子代理 ≥4（立项直接数）；20 万 tokens 作事后校准；按规模选**三档裁剪**：全量档（六阶段全套）/ 标准档（简化台账走查）/ 轻量档（只留目标卡+契约+任务清单+进度总览）；单人多角色场景另有裁剪（写权降级、跨模型走查强制）。

## 四、个人 + AI vs 团队速查

| 机制 | 个人 + AI | 团队 |
|:---|:---|:---|
| 拆分粒度 | 一个会话装得下 | 3 人天 |
| 责任机制 | 执行载体四选一（默认后台子代理，DSH 能力） | RACI 矩阵 |
| 验收复核 | Ralph 验证轮（可选） | Code Review |
| 同步 | 进度总览更新 + 周复盘 | 站会 + 周会 |
| 变更审批 | 三级分级：登记免确认 / 轻评审 / 实时确认 | 周五统一审 |
| 评测门槛 | 契约校验器 + P0 100% | 同上 + 覆盖率 ≥60% |
| 签字 | 用户签验收单 | 四方签（产品/技术/业务/安全） |

## 五、两条硬规矩

1. **文档即事实源**：docs/ 唯一真理源，工具记忆只是缓存；
2. **状态推进只认证据**：没有命令+输出证据就不算完成——对 AI、对人都一样。
3. **证据链存放（V2.2）**：命令+输出证据存 `docs/证据/`，随交付报告归档；复验时按交付报告路径取回，有效期至项目复盘归档。

## 六、常见坑（定稿版）

- PRD 流水账没有「不做的范围」；契约没有 schema 和校验器。
- 任务包切太大，单会话爆上下文；切太碎，接口暴增。
- 施工图没画到"零思考"就开工——执行会话卡壳、反复请示。
- 走查用同一模型做——共同盲区，必须跨模型/跨工具。
- 契约细化时改编号——施工图引用全部失效，只补子条目。
- 跳过组装直接宣布完工；总验收不查漏项/蔓延。
- 把"AI 说完成了"当完成；文档与代码漂移不自检。
- 只定止损线不定义触发动作；评测集随意改（改尺子）。
- 把性能/成本验证全留到竣工压测——返工穿透多个阶段（施工图就写预算，逐环验证）。
- 上线后不复盘——下个项目重踩坑。
- 文档只增不归档——机制自己变成负担（用归档约定）。

## 七、文档索引与归档约定（评估强化）

- 每项目建一份**文档索引**（活文档清单：路径 + 状态 + 责任人）；
- 过时文档移入 `归档/` 子目录，不删除、不堆积在主目录；
- 每份活文档头部注明状态（草稿/冻结/已通过）。

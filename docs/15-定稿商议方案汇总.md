## 三、各阶段融合设计要点

**1 立项**：目标确认卡（真实目标/完成标准/范围边界/关键约束 + 止损线含触发动作）→ 先查后造 → 数据资产盘点 → 技术路线 2~3 候选（用户拍板留档）→ PoC = 最小验证（先试最险点，不成立回退）→ 总框架（PRD 定稿 F1/F2 编号 + 契约骨架 + 评测基线冻结）。

**2 详细设计（施工图设计）**：双明确准入（需求冻结 + 方法冻结，任一不满足回退）；设计三方面——主体框架设计、功能设计、装饰美观设计；每个后续任务一张施工图（七要素：施工内容/施工方法分步/材料清单引用契约/质量验收标准/边界异常/工期/关联需求）；**100% 完美设计标准**（零思考走查：新会话按图执行，需思考处=图没画到位，补图后再评审）；施工图冻结（变更走变更单）。

**3 实施**：施工图分册成任务包（粒度=一个会话装得下）→ 制定任务包级上下游接口契约 → 分包施工（照图施工，零设计决策）→ 分包过程验收（独立跑校验器+评测集，P0 100%）→ 多线管理（进度总览+状态门+红黄绿灯）。执行载体四选一：后台子代理（默认）/DSH goal 续轮/Ralph 验证轮/真新会话。

**4 组装**：按数据流逐环联调（schema 校验逐环过，不过→定位模块打回）→ 总验收（对照 PRD 验收标准逐条 + 需求追踪查漏：无主需求=漏项、无源功能=蔓延）→ 整改（缺陷闭环：Badcase 台账、归因四层、回归入集须走变更单）。

**5 竣工**：全链路压测、安全合规审查、验收单签字、竣工图归档（实际快照）、回滚预案、上线。

**6 运维**：三维监控（效果/性能/成本）、漂移检测、badcase 持续闭环、数据回流、定期评测、复盘入库（反哺下一项目立项，闭环回起点）。

## 四、拆分规则（六条，用户追问确定）

1. **内聚最大化、接口最少化**：常一起变的放一包；包间只留最小接口（接缝最少处切刀）。
2. **按依赖方向拆**：S0 骨架 → S1 数据 → S2 功能 → S3 界面；互不依赖的标并行。
3. **粒度规则**：一个会话装得下（宁小勿大）+ 每个包必须可独立验收（有明确输入/输出/验收标准，不能独立验收的拆分是无效拆分）。
4. **易变隔离**：预计会变的需求圈进少数模块。
5. **按施工图分册**：拆分不另起炉灶，图纸决定拆分。
6. **拆完预演执行**：任务包开场白模拟执行，执行者需追问处=接口没定义清，打回补。

保证"拆了好做"的配套：任务包自包含（上游接口/下游接口/验收标准/施工图编号全在包里）、粒度匹配执行载体、前几个包执行经验回喂后续拆分。

## 五、组装机制（模块化生产类比，用户追问确定）

| 用户的类比 | 机制实现 |
|:---|:---|
| 模块完美连接 | 接口契约 = 标准连接件（只通过契约通信，不直读内部） |
| 连接合格保证 | 校验器 = 出厂/现场检具（schema 校验） |
| 完美连接靠什么 | 提前定义 + 契约冻结（各包并行对着同一份契约生产） |
| 组装怎么进行 | 按数据流逐环联调，过→下一环，不过→定位模块打回 |

三层保障：静态层（schema 校验）→ 动态层（契约级测试）→ 集成层（端到端联调）。组装 ≠ 完工。诚实提醒：连接失败是正常事件，机制保证"失败可定位、可修复、可追溯"而非"永不失败"。

## 六、施工图设计标准：100% 完美设计 + 5% 瑕疵处置方案（用户修正）

- **设计标准**：按 **100% 完美标准**出图——每个任务都画到位，零思考走查要求通过，不留设计空白。不做"画个大概等现场补"。
- **瑕疵处置方案**：预设约 5% 的瑕疵发生率（预算预期，非质量容忍），三级处置：

| 级别 | 类型 | 处置 | 是否停工 |
|:---|:---|:---|:---|
| A 类 | 施工图缺陷（图错/图漏） | 补图改图 → 变更单升版 → 受影响包重走验收 | 暂停该任务 |
| B 类 | 执行偏差（照图做但偏了） | 记录纠正 → 回归验证（不涉图） | 不停 |
| C 类 | 外部变化（需求/环境变） | 走变更通道 → 评估影响范围 | 按评估 |

瑕疵流程：发现 → 当天录台账 → 分级 → 处置 → 回归验证 → 关闭。时间余量呼应原手册 15%~20% 缓冲。

## 七、三个优化点（已与用户确认）

1. **画图成本上限**：施工图设计成本 < 返工成本；需求+方法明确的画细，不明确的按"近端细化"（开工前补图）。
2. **装饰美观设计须人工评审**：美观类施工图模型可给方案，最终判断必须人确认（模型弱项）。
3. **并行度受控**：子代理 3~4 个一批，多线并行但总控成本受控。

## 八、贯穿暗线（全程生效）

1. 状态门 + 进度总览（任何会话/工具先读再干活；只认证据：命令+输出）
2. 变更通道（改契约/施工图/PRD：停下 → 用户确认 → 升版 → 补任务包）
3. 文档即事实源（docs/ 唯一真理源，工具记忆只是缓存）

大模型适配性结论（已与用户达成共识）：文档驱动分步执行、外部记忆、输出必须验证、上下文小而专、人机分工（人管方向决策验收，模型管生成起草执行）、最小验证先行——本方案适配所有通用大模型（机制建立在无记忆/上下文有限/需验证的通用特性上），不同模型只调触发线与任务包粒度。

> 上游接口：阶段 2《分项施工图》（任务清单、任务边界）、《施工图设计总说明》（契约骨架、评测基线）
> 下游接口：向阶段 4 输出已通过模块 + 交付报告 + 需求追踪映射表；向阶段 5 输出验收证据链

## 一、阶段定位（用户原话要旨）

"将施工图项目拆分，制定上下组装接口契约，分包施工，分包过程验收，形成多线管理"——实施阶段 = 施工组织 + 照图施工 + 过程管控，**执行零设计决策**。

## 二、融合后完整流程

### 步骤 1：拆分（施工图分册 + 六规则）
把《分项施工图》按任务边界**直接分册**成任务包 S0/S1/S2…，拆分不另起炉灶。**拆分六规则**：
1. **内聚最大化、接口最少化**：常一起变/一起用的放一包，包间只留最小接口（接缝最少处切刀）；
2. **按依赖方向拆**：S0 骨架（无依赖）→ S1 数据 → S2 功能 → S3 界面；互不依赖的标并行；
3. **粒度规则**：一个会话装得下（宁小勿大，半个会话能完成最好）+ **每个包必须可独立验收**（明确输入/输出/验收标准——不能独立验收的拆分是无效拆分）；
4. **易变隔离**：预计会变的需求圈进少数模块；
5. **按施工图分册**：图纸边界（阶段 2 已按内聚最大化设计）就是拆分边界；
6. **拆完预演执行**：拿任务包开场白模拟执行，执行者需追问处 = 接口没定义清，打回补。

**任务包自包含**：上游接口（从哪拿什么）/ 下游接口（向谁交什么）/ 验收标准 / 施工图编号，全写进包内。

### 步骤 2：制定上下组装接口契约（任务包级细化）
在阶段 1 契约骨架基础上，细化到任务包级：
- **细化规则（评估强化）**：只补子条目、**不改编号**（施工图引用的契约条目编号不许变）；改编号 = 契约升版 = 走变更单，且四级连锁勾销（见步骤 5）；
- 各任务包并行开工前，契约冻结——所有分包对着同一份契约生产（像工厂对着同一份标准图纸）。
- **检具归属（V2.4）**：契约校验器、自动化评测流水线、变更比对脚本列为 **S0 级基础设施任务包**（先于功能包开工）；检具自身走独立验收并持有「检具回归样例」——防"检具盲区"（人人假设别人会建）；变更①级「机械判定」以比对校验器就绪为前提，未就绪时升级②级轻评审。

### 步骤 3：数据准备（评估强化：明示数据链路 + 合规门禁）
按数据规范执行：采集 → 清洗 → 标注/向量化 → **合规检查（V2.1）**（PII 脱敏核验、版权来源核验）→ 存储 → **版本入库（不可变存储：Git LFS / DVC / 对象存储）**；数据版本与模型/Prompt 版本可对账。**合规检查必须在版本入库前**——入库后再发现 = 污染不可变存储，修复成本翻倍。

### 步骤 4：分包施工（照图施工）
- **照图施工七条纪律**：①已读施工图+契约+进度总览再开工；②只做包内事，发现别的问题记录报告不顺手改；③要改契约/施工图 → 停下报告，确认升版再继续；④交付必须带契约级测试并跑通；⑤结束写交付报告并交总控（**进度总览与台账仅总控可写**，分包不直接写，V2.1）；⑥不得以"上下文长"跳过拆分；⑦照图施工零设计决策，图没画到处停下报告走变更单补图，不自行发挥。
- **执行载体四选一**（开工前选一次，中途可切）：①后台子代理（默认，总控只做派工简报、证据复核、进度更新）②DSH goal 自动续轮 ③Ralph 验证轮（验收前零历史新大脑复核）④真·新会话（用户自开新会话粘贴开场白）。
  > **依赖注明（评估强化）**：①②③ 是 DSH 工具能力；其他模型/工具只有 ④。跨工具场景按 ④ 组织。**无 DSH 执行模式（V2.2）**：纯④环境 = 串行分包 + 单线进度表 + 简化灯号（只保留"通过/受阻"两态）——多线管理机制不照抄，防止机制照搬但不适配。
- **并行度受控**：子代理 3~4 个一批，多线并行但总控汇总成本受控，不贪多。
- 每次实验记录参数/数据版本/结果（实验记录表）。

### 步骤 5：分包过程验收（照施工图逐条）
- 独立跑**契约校验器**（样例输入 → 断言 schema 输出）+ 独立跑**模块评测集**（P0 必须 100%）——验收人不写代码，只跑检具，不采信自报；
- **对照性能/成本预算（V2.1）**：延迟、单次调用成本对照施工图预算，超标 = 验收不通过——NFR 是架构属性，不带病进组装；
- **合规 P0 项（V2.3，LLM 应用强制）**：内容合规检测、Prompt 注入防护测试纳入分包验收 P0——安全合规不进竣工才查；
- 验收标准逐条附命令+输出；异常场景补测（空输入/超长/特殊字符/超时，对照错误码表）；
- 文档漂移检查：契约版本 vs 实际实现（校验器输出为证）；
- 通过 → 状态门"已通过"（附证据）；未通过 → 打回修复。

### 步骤 6：多线管理（进度总览 + 状态门 + 红黄绿灯）
- **进度总览**（状态面板 + 跨会话接力点）：任务包状态表（待开工/进行中/待验收/已通过/受阻）、需求追踪映射表（F1→任务包→证据）、变更登记、风险登记、瑕疵台账；**存储位置（V2.2）**：`docs/进度总览.md` **独立文档**（不是工具私有状态）；分包只读；总控会话崩溃 → 新会话读进度总览执行"接管仪式"续任；
- **状态门只认证据**：草稿≠通过；
- **红黄绿灯（V2.1 加成本维度）**：🟢全部 P0 通过进度正常；🟡P1 低于阈值或延迟<3 天；🔴P0 未通过或延迟≥3 天或重大阻塞，**或成本燃尽 >70% 而进度 <50%**；
- **止损线中途对账（V2.1）**：进度总览新增「累计投入（tokens/成本）vs 止损线」燃尽项，每次迭代更新；接近止损线（如 80%）时触发立项定义的触发动作复核——止损线不是竣工时才看的数字；
- **自动化评测流水线（评估强化保留）**：每次代码提交自动跑核心评测集，防退化；评测集变更走变更单；
- 瑕疵处置（阶段 2 五节的 5% 方案在此执行）：A 类暂停补图、B 类≥3 次升级 A、C 类走变更；瑕疵台账 = Badcase 台账（同一张）；瑕疵率触发复盘按 **02 §五双条件**（条数 ≥3 且比例 >5%；任务包 <10 只看绝对数）——**口径单一事实源在 02**；
- **分期竣工（V2.1）**：允许子集模块先走 4→5→6 小闭环（先上线垂直切片），降低大爆炸风险——分期是计划内的波次，不是变更。**最小独立交付单元（V2.3）**：分期单元必须具备完整业务闭环 + 独立契约边界 + 独立验收标准；**分期间不得共享未冻结契约**——分期不变成耦合。

### 步骤 7：变更与勾销（贯穿暗线落地，V2.1 三级分级）
- **变更三级分级（V2.1 核心修订，加兼容性维度）**：
  1. **登记免确认（V2.2 收紧判定主体）**：仅限**机械可判定**的变更——只新增条目号、不改动任何既有条目原文、不影响既有引用（由**校验器自动比对判定**，不由分包 LLM 自判）+ B 类执行偏差；直接处理，**24h 内补录变更单，保留一周撤销权**；
  2. **轻评审**：施工图补图（不涉契约语义）、评测集加用例——批量提报，用户抽批；
  3. **实时确认**：改契约**编号/语义**、改施工图冻结内容、改验收标准、**改 Prompt 行为定义**（系统 Prompt 语义、few-shot 结构）——停下→用户确认→升版→再继续。**注意（V2.2）**：施工图范围内的调参（参数扫描、措辞微调，验收标准不变）归①登记免确认——否则 Prompt 工程类任务会被实时确认卡死。
- 变更单字段：F 编号 / 契约条目（v__.__→v__.__）/ 施工图编号 / 任务包 / 评测集连锁 / **分级档位**；
- **四级连锁逐级勾销清单（评估强化）**：契约升版 → 逐级检查勾销：施工图（引用处）→ 任务包（受影响包）→ 交付报告（补证据）——勾完才关闭变更单；
- **批量变更（V2.3）**：同类型、同影响范围的多个轻量变更可合并提报、批量评审——降低管理开销，防止团队绕过流程。

### 角色与权限（V2.1 新增，RACI 简版——评审 P2-8）

| 角色 | 职责 | 边界/隔离 |
|:---|:---|:---|
| 用户 | 拍板、阶段 5 签字、③级变更实时确认、②级抽批 | 不兼任分包执行 |
| 总控 | 派工简报、**进度总览/台账唯一写方**、证据复核、汇报 | 不写分包代码 |
| 分包执行 | 照图施工、交交付报告 | 不写进度总览/台账 |
| 独立验收 | 跑校验器+评测集、逐条证据核对 | 不采信自报；个人场景可 Ralph 验证轮 |
| 走查人 | 施工图零思考走查 | 跨模型/跨工具 + 未参与设计 |

> **单人多角色场景（V2.2 人力维度裁剪）**：用户一人兼四职时——写权隔离降级为「文档写入与验收证据分离存放」（`docs/证据/` 独立目录）；**跨模型走查从"推荐"升级为"必须"**（自审已完全无隔离）；总控职责由用户 + 主会话承担。
> **物理隔离强化（V2.3）**：①验收强制使用**无历史上下文的全新会话**执行验收脚本，交付报告附独立会话完整输出日志；②**隔日验收**：施工完成后隔日再验收——睡一觉再查，弱化上下文记忆带来的自审偏差。

> **争议升级路径（V2.3）**：阶段准入争议 → 技术负责人裁定；需求变更争议 → 用户/业务负责人裁定。团队场景扩展 RACI（业务方/安全岗/运维岗的介入节点与决策权）在团队启用时补充。

## 三、检查清单

- [ ] 任务包拆自施工图分册（六规则满足；每个包可独立验收、自包含）
- [ ] 任务包级契约已细化（不改编号、只补子条目）并冻结
- [ ] 数据准备按规范版本入库（不可变存储）
- [ ] 分包施工照图执行（纪律七条自查；执行载体已选；并行度受控）
- [ ] 分包验收独立跑通（校验器 + 评测集 P0 100% + **性能/成本预算对照**，证据在案）
- [ ] 文档漂移检查通过（契约版本 vs 实际实现）
- [ ] 进度总览每日/每迭代更新（状态门只认证据；红黄绿灯判定有据）
- [ ] 自动化评测流水线运行（每次提交自动跑评测集）
- [ ] 瑕疵台账当天录入、分级处置（B≥3 次升级 A；瑕疵率 >5% 已复盘）
- [ ] 变更走单 + 四级连锁逐级勾销（三级分级档位明确）
- [ ] **写权隔离执行**（进度总览/台账仅总控可写；角色 RACI 执行在案）
- [ ] 每个任务包交付报告六节齐全（含文档漂移证据）

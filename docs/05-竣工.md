# 阶段 5：竣工（竣工验收 + 竣工图 + 上线）——6 阶段定稿版

> 上游接口：阶段 4《总验收结论》+ 全部已通过模块
> 下游接口：向阶段 6 输出《竣工图》（运维对比原点）+ 线上值班交接

## 一、阶段定位（用户原话要旨）

"竣工"——工程竣工验收：签字、归档竣工图、上线交付。**签字对象是阶段 4 的《总验收结论》，本阶段不重复验收**（边界写死）。

## 二、融合后完整流程

### 步骤 1：全链路压测（上线前最后验证）
并发、延迟、稳定性、资源占用、成本（对照**施工图性能/成本预算（阶段 2）+ 立项止损线（阶段 1）**，V2.4 修正基准引用——与成本三列口径一致）。
- **压测不通过处置（V2.2）**：按 04 打回机制定位——性能问题先查 04 增量压测漏环 → 回 04 整改子流程；架构性超标 → 回 03（走变更单）。

### 步骤 2：安全合规审查
数据脱敏、权限、敏感词、审计日志、内容安全。

### 步骤 3：验收单签字
- 对照阶段 4《总验收结论》逐条复核签字（产品/技术/业务/安全；个人+AI 场景 = 用户签字）；
- **核心验收单独签字（V2.5）**：核心验收指标必须由用户本人亲验签字（实际玩过/用过/核过准头），AI 不得代判代签；**核心未亲验 = 不予竣工**；
- 签字只签总验收结论，不重复验收。
- **真实交付演示（V2.7）**：签字前用户**真机走一遍**（打开→操作→达成目标），对应需求链「使用层」结果；演示卡壳 → 回 04 整改——交付不只是交代码，是交"用户能用"。

### 步骤 4：竣工图归档（实际 ≠ 设计）
实际上线版本的完整技术快照：
1. 模型/Prompt 快照（最终 System Prompt 全文、few-shot、模型版本、关键参数）；
2. 数据快照（数据版本号、向量库版本、数据分布对比）；
3. 性能基线（评测集指标精确值、压测结果、单次调用成本）；
4. 接口快照（最终契约 vs 设计文档差异说明、错误码清单）；
5. 已知问题清单（未修复 P1/P2 及规避方案、模型能力边界）。
> 竣工图 = 阶段 6 运维的**对比原点**（所有监控/评测对比它）。

### 步骤 5：回滚预案 + 上线
- 回滚步骤明确、责任人明确、回滚时间窗口确认；
- 监控告警配置（效果/性能/成本/异常四维度）；
- **灰度上线（V2.2）**：小流量（5~10%）→ 观测（效果/性能/成本）→ 全量 或 回滚；与 06"可灰度、可回滚"的模型版本管理衔接；
- 上线后 7 天值班盯盘。

## 三、检查清单

- [ ] 全链路压测通过（对照施工图性能预算 + 立项止损线）
- [ ] 安全合规审查通过（脱敏、权限、敏感词、审计日志）
- [ ] 验收单已签（签阶段 4 总验收结论，不重复验收；**核心验收由用户本人单独亲签，未亲签不予竣工**，V2.5）
- [ ] 竣工图已归档（5 部分完整：Prompt/数据/性能/接口/已知问题）
- [ ] 回滚方案已准备（步骤、责任人、时间窗口）
- [ ] 监控告警已配置；上线后 7 天值班已排定
- [ ] 文档完整性终检（设计文档、接口文档、操作手册、应急预案）
- [ ] **真实交付演示完成**（用户真机走通，V2.7）

## 五、分期场景（V2.4，对接 03 分期竣工）

启用分期竣工（子集模块先走 4→5→6 小闭环）时：
- **每期产出分期竣工图 + 独立监控原点**（各期对比各自原点）；
- **末期总竣工汇总**：整体快照 + 各期索引（总竣工图 = 核心原点）；
- 多期并存按「可灰度、可回滚」机制管理多版本；
- 首个项目明确不分期 → 本小节标注「暂不适用」，但条款保留。
